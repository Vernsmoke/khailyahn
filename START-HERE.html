Start with a new, empty database. This package does not copy existing gym records or passwords.

1. Add your domain and enable HTTPS

  1. In Hostinger hPanel, add khailyahn.online to your hosting plan as a custom PHP/HTML website. Choose the empty/custom website option; no WordPress installation is needed.
  2. If Hostinger asks for DNS changes, apply the records shown in your account and wait until the domain resolves.
  3. Enable the SSL certificate and Force HTTPS. Use https://khailyahn.online as the single canonical address. Redirect www to it if you also use www.
  4. Under PHP Configuration, select PHP 8.2 or later. Enable pdo_mysql, mbstring, gd, fileinfo. Use 256 MB memory if available.

Menu names can vary. Hostinger PHP instructions.

2. Create an empty MySQL database

  1. Open the site's Databases → Management area.
  2. Create a new database, database user and strong database password. Save the complete database name and username including the Hostinger prefix.
  3. Open phpMyAdmin for that database. Select Import, choose database/schema.sql from this package, and import it once.
  4. Verify tables such as member, payment and user_account appear.

Use a fresh database. Do not import this schema into an existing production database or repeatedly import it. It intentionally creates no default accounts.

3. Upload the two archives

Open File Manager for the domain. The final layout must look like this:

│   ├── .htaccess          ← denies direct web access
│   ├── app.php
│   ├── core.php
│   ├── operations.php
│   ├── reports.php
│   ├── config.example.php
│   └── config.php        ← you create this in step 4
└── public_html/
    ├── .htaccess
    ├── index.html
    ├── api.php
    ├── setup.html
    ├── setup.js
    ├── setup.css
    ├── assets/
    ├── backgrounds/

  1. Inside public_html, upload UPLOAD-public_html.zip and extract its contents directly here. Avoid an extra nested public_html folder. Back up/remove any default index.php or old site that takes priority over index.html.
  2. Go up one folder, so you can see public_html. Upload UPLOAD-gym-private.zip here and extract it. It creates gym-private.
  3. Make sure .htaccess is present; enable “show hidden files” if needed.
  4. Delete uploaded ZIP files from the hosting account after extraction.

Do not upload the whole project. The database SQL, source, tests, and configuration must not be publicly downloadable. If File Manager will not let you go above public_html, contact hosting support for a private directory; do not put the credentials inside public_html.

4. Enter your database settings privately

Inside gym-private, copy config.example.php to config.php. Edit it in File Manager:

<?php
return [
  'db_host' => 'localhost',
  'db_port' => 3306,
  'db_name' => 'your_full_database_name',
  'db_user' => 'your_full_database_username',
  'db_password' => 'your_database_password',
  'app_origin' => 'https://khailyahn.online',
  'cookie_secure' => true,
  'setup_token' => 'a-new-random-token-at-least-32-characters-long',
];

Use the database host shown by Hostinger if it differs from localhost. Generate the setup token in a password manager; it must be a fresh random value, not the text shown above. Keep the quotes and commas. If a password contains a single quote or backslash, escape it in the PHP string or use a newly generated password without those characters.

Use the exact HTTPS domain with no trailing slash for app_origin. Choose restrictive private-file permissions supported by the host (typically 600 or 640 for config.php).

5. Create your real administrator

  1. Visit https://khailyahn.online/setup.html.
  2. Enter the setup token from the private config, your name, a unique username, and a password of at least 12 characters.
  3. After success, change 'setup_token' => '' in config.php. Delete setup.html, setup.js, and setup.css from public_html.
  4. Visit https://khailyahn.online/login and sign in.
  5. Use Staff & access to create individually assigned accounts. Keep a second trusted named Admin for recovery.

Setup automatically refuses to create another initial administrator once installed. There is no shared default password.

6. Verify before entering real records

Use a separate staging database for synthetic financial tests so test payments do not pollute your real ledger.

  • Check registration, annual-only denial, monthly payment, approved QR entry, and repeat scans.
  • Confirm staff cannot open revenue analytics, account administration, Activity Logs, or settings.
  • Try the actual gym camera over HTTPS; grant camera permission. Manual QR token entry is also available.
  • Test profile photos, QR downloads, logo changes and fees.
  • Log out and sign back in. Open /members directly and refresh it to verify routing.
  • Check that /server/config.php and /database/schema.sql return 403/404, never file contents.
  • Export and restore a staging backup, and verify payment totals.

The supplied local test results do not verify your Hostinger account, DNS, HTTPS, hardware camera, or backup schedule. Those need this final hosting check.

7. Keep a recoverable backup

Export the full database through phpMyAdmin after each business day, or more frequently according to how much data you can afford to lose. Pause staff writes during a manual export. Photos and branding are in the database.

Keep encrypted copies off the hosting account and a copy of the matching code archive. Test a restore into a new database. Weekly hosting backups alone may miss several days of payments and registrations.

Read README.md for update and recovery guidance. Never put SQL backups inside public_html.
